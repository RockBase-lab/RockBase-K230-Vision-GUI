# LVGL binding on CanMV K230

What this firmware's LVGL 9 binding actually exposes, how it renders, and the
API traps that silently produce wrong layouts. Read this before writing GUI
code.

## Rendering model

- The firmware runs LVGL in `DISP_RENDER_MODE.FULL`: **any invalidation
  repaints the whole screen**.
- `LV_DEF_REFR_PERIOD` is 30 ms, so the theoretical ceiling is 33 fps.
  Including `task_handler()` (5-8 ms) and flush (2-3 ms), the practical range is
  22-30 fps. The visual result is smear, not tearing.
- To raise the frame rate during interaction, call
  `lv.refr_now(disp_drv)` every frame while touching and for 400 ms after
  release.
- `lv.refr_now` is available on this firmware.

### repaint cost must be measured with invalidate + refr_now

Measuring with `task_handler()` is **wrong**: the 30 ms refresh period means
the loop often never triggers a repaint, which makes a slow widget look fast.
Always measure with:

```python
obj.invalidate()
lv.refr_now(lv.disp_get_default())
```

This distinction produced an earlier, incorrect conclusion that a slow font
was "fast after the first five frames".

## Fonts

### what is compiled in

Only four bitmap fonts exist: `font_default`, `font_dejavu_16_persian_hebrew`,
`font_montserrat_14`, `font_montserrat_16`. `font_montserrat_20/22/32/36/48`
exist in `lv_conf.h` but are **not exported by the binding** — in Python they
are `NoneType` or a function, not an `lv_font_t`.

Setting a non-font raises `Can't convert function to lv_font_t!` and kills
`open_app`. Wrap every font candidate in try/except and fall through to the
next one.

`lv.font_t` is a struct and exposes `.line_height`, which is usable for layout
math.

### runtime bin fonts are the answer for large or custom sizes

`lv.font_load("A:/sdcard/...bin")` works with fonts generated by the GitHub
master build of `lv_font_conv` using `--format bin --bpp 4 --no-compress`.

- The `A:` drive prefix is **mandatory**. Without it the call returns `None`
  silently — no exception.
- The npm release 1.5.3 is five years old and emits LVGL v8 format. The v9
  loader accepts it but the bitmap alpha is distorted.
- A 28 px Nunito Bold bin loaded this way renders crisply, and
  invalidate + `refr_now` over 5 frames costs 18 ms (about 3.6 ms/frame),
  comparable to `montserrat_16`.
- After loading once, repaint is a plain blit. Arbitrary sizes and custom glyph
  ranges therefore need **no firmware rebuild**.
- When writing a bin to SD, call `f.close()` explicitly. Inline
  `open(...).write(...)` never flushes and the file stays at 0 bytes.

Font assets in this repo are produced by `tools/gen_font.py`, whose `SPECS`
table defines size and glyph set. The assets land in
`factory/gui/assets/fonts/*.bin` and are deployed automatically.

### localized UI text uses a glyph subset, not a whole CJK font

The home screen carries Chinese labels, and the Latin faces (`Nunito`,
`montserrat`, `mono_dejavu`) have no CJK glyphs. The zh strings are baked into
`ui_cjk_28.bin` from Source Han Sans at 28 px, bpp 4, covering only the
characters `i18n.NAMES` actually uses (47 glyphs plus ASCII, 30 KB).

Measured on board: `lv.font_load("A:/sdcard/factory/gui/assets/fonts/ui_cjk_28.bin")`
costs 163 ms and 30 KB of LVGL heap, and a full-screen repaint with four mixed
ASCII/CJK labels costs under 1 ms (`refr_now` x10).

The same size is required on both bake paths: the offline
`tools/gen_tile_cache.py` rasterises tile names with Source Han Sans at 28 px,
and the on-board fallback bake uses the same `ui_cjk_28.bin`, so a cache miss
renders identically to a cache hit.

The full 3755-glyph GB2312 level-1 set was measured too: 876 KB on SD, 4688 ms
to load, ~860 KB of heap. This firmware's GUI runs with about 1.6 MB free while
an AI app holds its buffers, so a full CJK face would crowd out the
`release_home` applications. Keep UI CJK to the used subset.

### monospace digits

`tools/gen_font.py mono16` produces `mono_dejavu_16.bin` from DejaVu Sans Mono
at 16 px, bpp 4, ASCII 0x20-0x7E (4.6 KB). Every glyph measures exactly 10 px
wide on the board, against `montserrat_14`'s proportional 11 / 6 / 4 px for
`0` / `1` / `.`.

Use it for numeric readouts that must not jitter. Headers stay on montserrat
because that font carries no letters beyond ASCII.

### three conditions for non-jittering numeric readouts

Missing any one of them makes the text shake:

1. `TEXT_ALIGN.LEFT`. Right alignment pins the right edge, so the whole string
   jumps when a sign or a digit appears or disappears.
2. A fixed sign, `{:+.4f}` / `{:+.2f}`, so the minus sign does not pop in and
   out.
3. A monospace font, so glyph widths are constant. Combined with a fixed-width
   field, the columns never move.

### a label's width is resolved by the layout pass of its screen

`get_width()` on a label that has never been through layout returns 0, and it
does not refresh afterwards: `set_text` on an already-laid-out label keeps the old
width, and loading a second screen does not re-lay-out labels created for the
first. Measured while checking glyph coverage, where this read 0 or stale values
and looked like the font was broken.

Reliable pattern in a probe: create the screen and every label first, choose the
text, then `lv.scr_load(scr)` followed by two `lv.task_handler()` calls, and read
the widths at the end. One screen per measurement, not one screen reused.

Deleting the screen you just measured also makes every later label report 0,
because that screen is the active one; see the rule against deleting the active
screen.

### a missing glyph is a narrower box, not a blank

There is no error when the font has no glyph for a character: LVGL draws its
fallback box. So "text rendered without raising" proves nothing about coverage, and
the useful check is the advance width: present glyphs measure the font's full
width (16.00 px for `ocr_cjk_16`), missing ones do not. Compare a suspect string
against a control string of known-good characters rather than against an absolute
number.

### tiny_ttf and freetype are unusable for live text

- `lv.tiny_ttf_create_file("/sdcard/...ttf", size)` does render arbitrary TTF
  sizes at runtime, but it re-rasterises on every repaint. Under FULL render it
  measured **1411 ms per frame for nine labels**, and 3184 ms/frame when moving
  seven multi-size labels, 5779 ms/frame when changing the size.
- `lv.freetype_font_create(path, size, style)` builds a font (path without
  `A:`, style `lv.FREETYPE_FONT_STYLE.BOLD` = 2) but the glyph cache is
  disabled and the binding does not expose `freetype_set_cache_size`. A 36 px
  keyboard full repaint costs 485 ms/frame against 6.3 ms for
  `montserrat_16`.
- Conclusion: **any text that changes every frame must be a pre-baked bitmap.**
  App tiles, clock digits, status-bar icons, timer digits and multi-touch hints
  are all baked PNG or raw bin assets.
- A TTF must be an official statically compiled build. `fontTools`
  `instantiateVariableFont` output makes `stb_truetype` loop forever while
  rasterising — creation and metrics succeed, the first render hangs the board
  and even Ctrl-C cannot interrupt it. A variable TTF also renders as
  ExtraLight by default.

## Theme defaults that break hand-placed layouts

- **A default `lv.obj` carries about 20 px of `pad_left/right/top/bottom`**,
  not zero. Any self-built card or panel that positions children with absolute
  `set_pos(x, y)` must call `set_style_pad_all(0, 0)` first, otherwise every
  coordinate is shifted once by that padding. Symptoms: content bunched to one
  side, a row wider than designed so a horizontal scrollbar appears, and
  `align(BOTTOM_MID, 0, 0)` yielding a negative x (measured -22 px).
- **`lv.obj` also carries `FLAG.SCROLLABLE` by default.** If a panel ends up
  slightly narrower than its content after padding, a default scrollbar draws a
  thin `0xE0E0E0` line on the right edge, which reads as a stray white border.
  Self-built backdrops and panels must call `clear_flag(lv.obj.FLAG.SCROLLABLE)`.
- `lv.textarea` uses a light theme by default. Inside a dark card it looks like
  an unintended white frame; repaint `bg_color`, `border_color` and
  `text_color` explicitly.
- Buttons and objects carry a default border and shadow, including in the
  PRESSED state. `set_style_shadow_width(0, 0)` only affects the default state,
  so pressing still draws a large ring outside the widget. Clear the border and
  shadow per state.
- Five `set_size_mode` values (VIRTUAL / REAL / COVER / CONTAIN / SCALE /
  SCALE_DOWN) affect layout only, not rendering — all six render identically.
  `lv.img.set_size()` **crops**; it does not scale. And the binding exposes no
  `set_scale` / `set_style_transform_scale`. Downscale images at build time
  instead (this repo pre-renders 64 px member icons).
- `flex` `pad_column` defaults to **11 px** and `pad_all(0)` does not clear it.
  Call `set_style_pad_column(0)` explicitly or each page accumulates 11 px of
  drift.
- `set_style_max_width(w, 0)` and other style setters **require the selector
  argument**, otherwise `TypeError: takes 3 positional arguments`.

## Two enums that are easy to confuse

- `set_align(lv.ALIGN.xxx)` repositions the widget itself (equivalent to
  `lv_obj_set_align`) and **overwrites coordinates set by `set_pos`**.
- Text alignment is `set_style_text_align(lv.TEXT_ALIGN.xxx, 0)`.

Passing `TEXT_ALIGN.LEFT` to `set_align()` does not raise; the enum values
collide numerically and the widget silently jumps somewhere else. This caused
an extended hunt for a "coordinate bug" that was actually an API mix-up.

## Hit testing

- **`lv.obj()` is CLICKABLE by default**, including `lv.scr_act()`. A
  decorative child inside a button (badge, icon, label) swallows the hit test
  and does not bubble, because LVGL 9 has event bubbling off by default. The
  parent button's `CLICKED` then never fires. Symptom: tapping the icon body
  does nothing while tapping the blank edge works.
- Fix: `child.clear_flag(lv.obj.FLAG.CLICKABLE)` on every decorative child.
- `obj.get_children()` is not recursive and does not work in this binding. Do
  not use it to diagnose the object tree; infer from click-coordinate
  boundaries instead.
- `lv.indev_search_obj(root, point)` works and returns the deepest clickable
  object at that point. `obj.hit_test(pt)` behaves erratically (rejects
  subclassed buttons) — avoid it.

## Touch input (FT5316)

- Event codes: `1 = Up`, `2 = Down`, `3 = Move`.
- A single drag contains **multiple spurious Ups** — up to 12 samples per
  gesture. The real release is the **last** Up. Fast drags produce many
  Down/Up pairs and almost no Move (measured over 1 s: `ev = [1:43, 2:43,
  3:2]`).
- Gap between a spurious Up and the next contact point: p50 = 20-26 ms,
  max = 40 ms. `RELEASE_HOLDOFF_MS = 45` must exceed 40, or a mid-drag
  misjudged release causes an early snap.
- Do not judge press state from the set of events at the end of a batch; FT5316
  routinely splits a single press into a Down+Up pair inside one batch. Judge
  from whether the batch contained a Down or Move.
- `TouchScreen.read_raw()` returns `(x, y, event, track_id)`. `track_id` comes
  from a 4-bit driver field and is the only way to distinguish fingers. LVGL is
  single-pointer: only the primary contact drives `_pressed` / `_last_x` /
  `_last_y`; the rest are queued.
- Emitting a synthetic click in a probe: `obj.send_event(lv.EVENT.CLICKED,
  None)`. There is no `lv.event_send`.

### drag-to-page requires silence-based gesture boundaries

Two hard requirements, both learned from real failures:

1. Decide start and end by **silence timeout** (no new contact for more than
   60 ms means the finger lifted), not by Down/Up. The false-Up behaviour above
   makes a Down-based anchor reset accumulate zero displacement, which was the
   real reason "swiping does nothing".
2. Feed the pager the **latest contact position**, never the anchor. On frames
   with no new contact, passing the anchor recomputes displacement as zero and
   the page snaps back while the finger is still down.

When vertical motion dominates (`ady > adx * 1.5 + 20`), suppress paging for
the whole gesture.

## Rotation

```python
Display.init(ST7701, width=ALIGN_UP(800, 16), height=480,
             flag=Display.FLAG_ROTATION_270)
```

- The ST7701 on this board is mounted opposite to the SDK default landscape
  orientation, so 270 corrects it at the display layer.
- `TOUCH(0)` takes **no rotate argument**: the FT5316 driver's default rotation
  already matches the corrected display, so coordinates line up directly.
- `ALIGN_UP(800, 16) == 800` because 800 is a multiple of 16. An earlier
  assumption of 816 caused a detour.
- Accepted buffers per flag: `FLAG_ROTATION_NONE` and `_270` / `_90` accept
  800x480 and reject 480x800; `FLAG_ROTATION_180` does the opposite (it swaps
  to portrait), so do not use 180 for landscape.
- LVGL-level rotation exists but is not used here: the enum is
  `lv.DISP_ROTATION._0/_90/_180/_270` (not `lv.DISP_ROT_180`) and
  `set_rotation(rot, swap_xy)` takes two arguments.

## RTC and timezone

Displaying "NTP time eight hours behind" comes from these five facts:

- `time.localtime(epoch)` does **not** apply a timezone: it equals
  `gmtime(epoch)` and returns UTC fields. Add `tz * 3600` yourself.
- `machine.RTC().datetime(v)` treats `v` as **local time** on write and stores
  `v - tz`; on read it returns internal + tz. So what you write is what you
  read, independent of tz, while `time.time()` equals `v - tz`.
- `time.localtime()` with no argument equals `RTC().datetime()`.
- `time.time()` is the true UTC epoch.
- `machine.RTC().timezone(tz)` accepts only integer hours in -12..12.

Correct sequence:

```python
local_tm = time.localtime(epoch + tz * 3600)
RTC().datetime((y, m, d, weekday, h, mi, s, 0))
```

Changing the timezone afterwards needs no re-sync: the display shifts
automatically (measured tz 8 → 9 moves 13:34 → 14:34).

## WiFi scan semantics

- Once connected and stable for more than 3 s, `wlan.scan()` returns **zero
  entries in 0-1 ms** because the radio is locked to the current channel.
- Within the first 1-2 s after `connect()` succeeds, a scan still works
  (9-13 entries, about 1.5 s), then goes to zero after 3 s.
- After `wlan.disconnect()` and a 600 ms wait, a scan always returns entries
  (9-15, about 1.48 s). Reconnecting to the same AP takes about 4.0-4.3 s.
- The only reliable way to get the real AP list is therefore: disconnect, wait
  about 600 ms, scan, reconnect with stored credentials — roughly 6 s total.
- During the disconnect window `ifconfig()` is invalid, so the UI must cache the
  last IP or it flashes "-".
- `scan()` returns `rt_wlan_info` **objects** with attribute access (ssid is
  bytes), not dicts. `r.get()` raises AttributeError. `security` is an int
  bitmask (WPA2_AES_PSK = 4194308).
- `wlan.status('rssi')` reads about 14 dB optimistic (measured -44 against a
  true -58). Use the scan cache as the primary source and this only as a
  fallback for cold-start adoption.
- `wlan.connect()` **does not raise** on association failure; only the C layer
  prints `run connect failed.` and `connect()` returns normally with
  `isconnected()` staying False.
- The radio cannot be disabled: `w.active(False)` reports `Network (rt-smart)
  cannot be disabled.` After repeated failures the supplicant state machine can
  wedge and Ctrl-D will not recover it. See `reset-matrix.md`.

## Misc binding gaps

| Missing | Workaround |
|---|---|
| `lv.SCROLLBAR` | defensive `getattr(lv, "SCROLLBAR_MODE" / "SCROLLBAR")` |
| `lv.RADIUS` | use the raw `0xFFFF` circle constant |
| `lv.DISP_ROT_180` | `lv.DISP_ROTATION._180`, two-arg `set_rotation` |
| Some `lv.SYMBOL` entries | try a candidate name list with `getattr` |
| `os.path`, `os.makedirs` | build paths manually, per-level `mkdir` + catch `OSError` |
| `__file__` under `exec()` | try/except `NameError`, fall back to `/sdcard/factory/gui` |
| `lv.chart.set_axis_range` | `set_range(axis, min, max)` |
| `indev.add_event` | register per widget instead |
| `keyboard.set_map` | not callable from Python (segfaults, confirmed twice) |
| `image.resize()` | OpenMV-style `copy(x_scale=, y_scale=)` or `mean_pool` |
| `str.endswith(tuple)` | single suffix string only |
| `ulab.numpy` `flip` / `[:, ::-1]` | cyclic shift, not reverse — unusable |
| `np.clip` on int16 | promotes to int32, doubling WAV size |
| LVGL `COLOR_FORMAT.RGB888` | reads **B,G,R**; `swap_rb()` first |
| 32bpp rendering | processes 4 pixels at a time, so image width must be a multiple of 4 |
| `hashlib.sha256()` | no `hexdigest()`; use `binascii.hexlify(h.digest())` |
| `ast` / `importlib` | execute only module-level helpers via string split |

## lv.chart measured behaviour

- API surface: `lv.chart(parent)`, `set_type(lv.chart.TYPE.LINE)`,
  `add_series(lv.color_hex(c), lv.chart.AXIS.PRIMARY_Y)`,
  `set_next_value(series, int)` **on the chart, with a series argument**,
  `set_point_count(N)`, `set_range(axis, min, max)`,
  `set_update_mode(lv.chart.UPDATE_MODE.SHIFT | CIRCULAR)`,
  `set_div_line_count(xn, yn)`. A series instance has only the attributes
  `color`, `hidden`, `x_points`, `y_points`, `start_point` — no methods.
- Repaint cost under FULL render, 800x480, `refr_now` per frame:
  empty baseline 0.21 ms; N=60 → 6.8 ms; N=120 → 10.9 ms; N=200 → 17.2 ms;
  N=300 → 24 ms (over the 20 ms budget). Roughly 2.4 ms + 0.074 ms per point.
  Within a 20 ms budget including a 1.7 ms I2C read, N ≈ 230 is the ceiling and
  N ≤ 150 is the safe zone.
- `SHIFT` moves the plot by `plot_w / (N - 1)` per `set_next_value`. Push every
  frame at the refresh rate for smooth motion; the window duration is
  `N / 50` seconds.
- A large canvas is not an option: 800x372 ARGB8888 `fill_bg` alone costs
  **73 ms** and twenty full-width 10 px lines cost 200 ms, while screen widgets
  are an order of magnitude cheaper (full-screen colour fill 3.7 ms, a 1000 px
  thick line 3.6 ms). A large RGB565 canvas OOMs the board outright.

## Snapshot capture without a display

Headless LVGL works: `lv.init()`, `disp_create(800, 480)`, ARGB8888, then
`set_draw_buffers(b1, b2, b1.size(), lv.DISP_RENDER_MODE.FULL)` (**four
arguments**, the third is the buffer size) with a flush callback that only
calls `flush_ready()`.

Capture with `lv.snapshot_take(lv.scr_act(), lv.COLOR_FORMAT.ARGB8888)`. Read
pixels by extracting the pointer first —
`ptr = int.from_bytes(bytes(memoryview(dsc.data)), "little")` — then
`uctypes.bytearray_at(ptr, w * h * 4)`. Reading the wrapper struct directly
yields garbage. Memory order is B, G, R, A.

`lv.scr_load(scr)` followed by two `lv.task_handler()` calls is required before
`get_y()` reports post-layout values.

A full-screen snapshot of `lv.scr_act()` needs about 1.5 MB of contiguous heap.
It succeeds when the launcher and app are built and free heap is around 2.1 MB,
and fails in tighter probe contexts.
